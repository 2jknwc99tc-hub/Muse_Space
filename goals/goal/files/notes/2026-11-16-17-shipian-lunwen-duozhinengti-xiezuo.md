## 一句话

多智能体协作的真实收益并不来自 agent 的数量，而来自协作的结构：状态、约束、对抗、拓扑四层逐层递进，几乎所有的失效模式都能归结为这四层结构中的某一处缺陷。

## 关键点（转述，非原文照抄）

1. **问题的起点：同一个方向，为什么有的地方显著提升，有的地方近乎无效**：多智能体系统（Multi-Agent System，MAS）正处在一个微妙的节点，一方面，从斯坦福的生成式智能体小镇到微软的 Magentic-One，让多个大模型协同工作被寄予厚望；另一方面，2025 年 Cemri 等人提出的失败模式分类学 MAST 给出了一个反直觉的结论：这类系统在主流基准上的性能增益“往往很小”。同一个技术方向，为何既能显著提升数学与代码能力，又在多数场景下近乎无效？本文拆解 10 篇有代表性的论文，试图论证一个更根本的判断：多智能体协作的真实收益，并不来自 agent 的数量，而来自协作的结构，具体而言，收益来自四个逐层递进的机制——状态、约束、对抗与拓扑；而几乎所有的失效模式，都能归结为这四层结构中的某一处缺陷。
2. **第一层，状态与角色：多智能体引入了单模型缺失的“时间维度”**：单模型推理在架构上存在一个结构性局限：每一次前向计算都是无状态的，给定同一个问题，模型要么答对、要么答错，它没有一个“自己此前的经历”可供调用，也就无法在错误的基础上进行真正的自我修正。所谓“自我修正”之所以常常失效，根本原因在于“生成答案”与“评估答案”使用的是同一套参数、同一套倾向——错的模式会一起错。多智能体的第一层价值，正是把这种无状态的单次生成，替换为有状态的持续交互。斯坦福大学 Park 等人（2023）的 Generative Agents 是这一思路的开端，他们在小镇 Smallville 中部署了 25 个智能体，每个智能体都配备了三件套：记忆流（memory stream，带检索评分的长期记忆）、反思（reflection，把具体经历抽象为高层见解）与规划（planning，基于记忆与反思制定行动）。这篇工作关注的不是解题，而是观察：当个体拥有了跨时间累积的状态，一群智能体会涌现出单模型看不到的社会行为——传八卦、组织聚会、形成关系网络，它论证的是“多智能体”作为社会现象的存在，而非一个任务工具。同年 KAUST 的李国豪等人（2023）提出的 CAMEL，则用“角色扮演”这一更轻量的方式引入了结构，CAMEL 通过 inception prompting 先让一个“任务规约器”把开放任务规约为具体的角色与分工，再让两个智能体分别扮演用户与助手，彼此派活、自主协作，实验中出现了一个设计者没有写入代码的行为：角色翻转——智能体会自发地互换身份，甚至替对方提出更合理的问题。这一现象说明，角色结构不只是约束，它同时为生成提供了一个更明确的上下文，降低了开放任务中的不确定性。这两篇工作的共同机制可以概括为：用显式的状态与角色，对抗单模型推理的无状态性。但仅仅引入角色并不足以解决任务正确性的问题——它只解决了“持续交互”的形态，尚未触及“协作如何产生正确结果”，这正是后续工作要回答的。
3. **第二层，SOP 与结构化中间产物：约束生成空间以对抗级联幻觉**：多智能体系统真正开始解决任务，是从“分工”切入的；而分工要有效，关键不在于分配了多少角色，而在于如何约束角色之间的信息传递。这里需要先厘清一个现象：级联幻觉（cascading hallucination），当多个大模型被简单地串联成链时，上游智能体的幻觉会成为下游智能体的输入，误差沿链路逐级放大，最终导致逻辑不自洽，MetaGPT 的作者在论文中明确指出，这正是此前“朴素串联”式多智能体系统的症结。MetaGPT（ICLR 2024 口头报告）给出的解法是把标准作业流程（Standardized Operating Procedures，SOP）编码进提示序列，它把一家软件公司的角色——产品经理、架构师、工程师、QA——组织成一条装配线（assembly line），每个角色产出的不是自由文本，而是结构化的中间产物：需求文档、设计文档、代码。这一设计的关键在于，结构化的文档 schema 把一个开放的生成空间，收窄成了字段受约束的填充任务，从而显著降低了每一步出错的概率，效果是直接的：在 HumanEval 与 MBPP 上分别取得 85.9% 和 87.7% 的 Pass@1，超越了此前的对话式多智能体系统。清华大学 Qian 等人（2023，ACL 2024）的 ChatDev 从另一个角度解决了同一问题，它用 chat chain 规定智能体“沟通什么”，用 communicative dehallucination 规定它们“如何沟通”，更有意思的是文中一个被广泛引用的发现：在系统设计阶段，自然语言沟通更有效；而在调试阶段，切换到编程语言更有效。这个结论的深层含义是，分工的价值不在于“人多”，而在于让不同阶段使用“对的语言”来压缩信息、减少歧义，ChatDev 最终以不到 1 美元的成本、约 7 分钟的时间，完成一次小型的端到端软件开发。MetaGPT 与 ChatDev 殊途同归：对抗级联幻觉的钥匙，都是“约束中间状态”，前者用结构（文档 schema），后者用语言切换（自然语言/代码），这构成了多智能体增益的第二层机制——结构约束。
4. **第三层，辩论与反思：从自一致性到群一致性的信用分配难题**：约束中间状态能减少误差的传递，但它不能主动发现错误，第三层机制——对抗——试图解决的是“如何让系统自己发现错误”。Du 等人（2023）提出的多智能体辩论（Multi-Agent Debate，MAD）是这一思路的代表作，其做法是：多个模型实例各自提出答案与推理过程，然后在多轮交互中互相质询、辩论，最终收敛到一个共同答案，实验结果报告了数学与策略推理任务上的显著提升，以及对事实性错误和幻觉的抑制。此外，MAD 不需要访问模型内部状态，可直接应用于黑盒模型——这使它区别于依赖中间层表征的方法。MAD 的机制本质，是把单模型的“自一致性”（self-consistency，即多次采样多数投票）升级为“群一致性”：多个实例不再是同一倾向的重复采样，而是彼此充当外部批判者，暴露各自推理链中的脆弱环节，这比单模型的自我纠错多了一层信息——一个用不同采样路径生成、因而可能不共享同一错误模式的视角。但这里藏着一个关键的信用分配（credit assignment）问题：辩论带来的增益，究竟来自“辩论”这个交互过程，还是仅仅来自最后“聚合多个答案”的步骤？后续研究（包括第 4 节的规模实验）逐步表明，相当一部分增益其实来自聚合，而非辩论本身。这个问题之所以重要，是因为它直接决定了工程资源应投向“更复杂的交互协议”，还是“更充分的采样与投票”。信用分配的不清晰，是理解“为什么很多多智能体系统看起来有效、实则没有增益”的一把钥匙。
5. **第四层，规模的两副面孔：倒 U 曲线与协作规模化定律**：如果增益来自聚合而非交互，那么一个自然的推论是：干脆多采样几个 agent 投票即可，但规模实验给出的答案比这更微妙，也更值得玩味。Li 等人（2024）的《More Agents Is All You Need》做了最直接的实验：用纯粹的采样加投票（sampling-and-voting，他们称之为 Agent Forest）把 agent 数量放大，结论是性能随 agent 数量呈现先升后降的倒 U 形趋势，且最佳数量与任务难度相关——任务越难，需要的 agent 越多。其机制不难理解：所有 agent 都从同一个底层模型采样，当数量超过一定阈值后，新增 agent 带来的多样性收益递减，冗余候选反而稀释了投票的有效性，换句话说，无结构的同质采样存在边际信息增益递减。几乎同期，清华 Qian 等人（2024）在 MacNet 中给出了看似相反的结论，MacNet 用有向无环图（DAG）把 agent 组织成协作网络，在其上对交互式推理进行拓扑编排，宣称可支持超过一千个 agent 的协同，作者还报告了一条“协作规模化定律”（collaborative scaling law）：整体性能随 agent 数量呈 logistic（S 形）增长，且不规则拓扑优于规则拓扑，协作涌现的发生早于传统神经网络的涌现。同样“加 agent”，一篇得到倒 U 曲线，一篇得到持续 S 形增长，这一分歧的根源不在数量，而在拓扑：More Agents 的 agent 是无结构的冗余采样，同质性强、边际信息递减；MacNet 的 agent 则占据 DAG 中的特定位置，其输入输出由拓扑决定，每一个 agent 都承载着图结构赋予的、不可被简单替代的信息。两者的对比与神经网络的规模律形成呼应：增加神经元有效的前提，是网络结构允许信息有效流动；同理，增加 agent 有效的前提，是拓扑允许信息被有效编排，数量本身不是杠杆，结构才是。
6. **十四种失败模式：一张可测量的失效图谱**：前述张力最终要落到一个可操作的问题上：多智能体系统究竟为什么会失效？Cemri 等人（2025）的《Why Do Multi-Agent LLM Systems Fail?》给出了迄今最系统的回答。这项工作构建了 MAST-Data——一个覆盖 7 个主流多智能体框架、包含 1600 余条标注轨迹的数据集，并在此基础上提出首个多智能体系统失败分类学 MAST，经专家标注并验证（标注者间一致性 kappa = 0.88），MAST 识别出 14 种失败模式，归入三大类：系统设计问题（system design issues）、智能体间错位（inter-agent misalignment）与任务验证缺失（task verification），分析覆盖了 GPT-4、Claude 3、Qwen2.5 与 CodeLlama 等模型，以及编程、数学与通用智能体任务。这项研究最耐人寻味的结论，正是开头提到的那句：多智能体系统在流行基准上的性能增益往往很小。更关键的是，MAST 的失败模式分布揭示了一个规律——多数失效并非模型能力不足，而是协作结构设计上的缺陷：角色边界不清、中间验证环节缺失、智能体间目标错位。这与第 2 节（约束中间状态）和第 4 节（拓扑编排）的结论形成了闭环：把失败模式做成一张可测量的图谱，是多智能体研究从经验性调参走向工程科学的必要一步。
7. **拓扑成为优化对象：从手工编排到自动搜索**：如果结构是多智能体增益的真正来源，那么合乎逻辑的下一步，就是把结构本身当作优化对象。Zhang 等人（ICLR 2025）的 AFlow 把这一想法推到了前台，它将工作流优化重构为“代码化工作流”上的搜索问题：工作流被表示为由节点（LLM 调用）与边（依赖关系）构成的代码，然后用蒙特卡洛树搜索（MCTS）在该空间上自动探索，通过代码修改、树状经验与执行反馈迭代精化，在 6 个基准数据集上，AFlow 相对最优基线平均提升 5.7%；更有意思的是，它能让更小的模型在特定任务上以 GPT-4o 约 4.55% 的推理成本反超后者。微软 Fourney 等人（2024）的 Magentic-One 代表了同一方向的工程实践，它采用中心化编排器（Orchestrator）加一组专用智能体（WebSurfer、FileSurfer、Coder、ComputerTerminal），用任务账本与进度账本协调各智能体的分工，其设计要义在于：把“谁在何时做什么”从各智能体的自由对话中剥离出来，交给一个显式的编排层。当协作拓扑本身成为可搜索、可优化的对象时，第 4 节的问题就被重新表述了：争论不再是“要不要更多 agent”，而是“工作流如何被搜索与编排”。这一转向与 AutoML 及神经架构搜索的演进同构——从手工设计转向自动搜索，是多智能体研究走向成熟的一个标志。
8. **结论与留给读者的工程问题**：把上述 10 篇论文连起来看，多智能体协作的增益可以归纳为四个逐层递进的机制：状态（记忆与角色，对抗单模型的无状态性）、约束（SOP 与结构化中间产物，对抗级联幻觉）、对抗（辩论与群一致性，外化批判视角）、拓扑（DAG 编排与工作流搜索，让规模成为可优化对象）。而与之对应的失效模式——角色坍缩、同质性冗余、信用分配不明、拓扑未优化——几乎全部指向同一件事：没有结构的协作，本质上只是昂贵的采样。这或许是多智能体领域当前最值得记住的一个判断：在一个又一个 agent 被“堆”进系统的当下，决定收益的从来不是 agent 的数量，而是它们之间的结构。文章最后留了一个问题：如果多智能体的收益主要来自结构而非数量，那么工程上更值得投入的，是精心设计编排拓扑，还是干脆回到单模型的多采样与自一致性？

## 与 Nakamura 现有工作的关联

- **与第九篇多智能体直接呼应，是第九篇的升级版**：第九篇讲的是多智能体协作的拓扑学，分开画通信图和控制图，任务合同要写清输入、输出、验收和缺项阻断，聚合之前先验证证据；这篇把同一套问题系统化为四层机制：状态、约束、对抗、拓扑。第九篇的“死锁与活锁、外部监督者、三层超时”对应这篇的 MAST 失败分类学，第 9 篇的“多数投票不等于事实、自报置信度不等于校准概率”对应这篇的信用分配难题。两篇合起来，多智能体协作的设计清单就是：先给每个 agent 状态和角色，再用结构化中间产物约束信息传递，再用对抗发现错误，再用拓扑编排规模，最后用 MAST 的 14 种失败模式逐项检查。
- **与第十六篇 SwarmEvolve 呼应**：第十六篇说 450 个 agent 在潜空间里交换 KV 缓存，达到其他框架 1 小时成绩只要 3–8 分钟；这篇提醒，数量本身不是杠杆，结构才是：无结构的同质采样存在边际信息增益递减，性能随 agent 数量呈倒 U 形，只有拓扑允许信息被有效编排，增加 agent 才有效。两篇合起来，SwarmEvolve 的潜空间通信要放在这篇的四层框架里看：它解决的是通信效率，拓扑、验证和信用分配仍然需要另外设计。
- **与第十四篇 EigenFlux 呼应**：第十四篇说 Agent 会从工具进化成主体，未来最强的 Agent 可能拥有最强的 Network；这篇说拓扑成为优化对象，从手工编排到自动搜索，AFlow 用 MCTS 在代码化工作流上搜索节点与边的组合。两篇合起来，Agent Network 的身份、信誉、发现机制是网络层，AFlow 的工作流搜索是编排层，两层都要有，缺一不可。
- **与第十五篇 Mercor 呼应**：第十五篇说评测就是验证，谁能为一个领域建立评测，强化学习就能把那套评测刷到饱和；这篇的 MAST 失败分类学正是评测的反面：一张可测量的失效图谱，多数失效并非模型能力不足，而是协作结构设计上的缺陷，角色边界不清、中间验证环节缺失、智能体间目标错位。两篇合起来，评测要同时测“做对了什么”和“怎么错的”，后者就是 MAST 的 14 种失败模式。
- **与第十三篇流程呼应**：第十三篇说流程要把经过验证的业务方法沉淀下来，让个人经验成为组织能力；这篇的 MetaGPT 把 SOP 编码进提示序列，用装配线组织产品经理、架构师、工程师与 QA，结构化的文档 schema 把开放的生成空间收窄成字段受约束的填充任务。两篇合起来，SOP 就是流程的 agent 版：约束中间状态，让每个角色产出结构化的中间产物，而不是自由文本。
- **对 AI 物业试点的直接启示**：试点方案如果要上多智能体，不能只堆 agent 数量，要先按四层设计：每个 agent 的状态和角色是什么，中间产物用什么结构约束，错误由谁发现（对抗还是外部监督者），拓扑是手工编排还是自动搜索；上线前用 MAST 的 14 种失败模式逐项检查，角色边界不清、中间验证环节缺失、智能体间目标错位是最常见的三类失效。
