# EigenFlux：下一个十亿级网络，可能不属于人类

- 记录日期：2026-11-16（北京时间）
- 标题：EigenFlux：下一个十亿级网络，可能不属于人类

## 一句话

Agent 会从工具进化成主体，数量爆炸之后真正缺的不是更强的模型，而是让 Agent 之间彼此发现、信任、协作的基建，也就是一张跨模型、跨产品、跨组织的开放 Agent 网络。

## 关键点（转述，非原文照抄）

1. **从工具到主体**：每一次经济活动的规模化跃迁，背后总有一次基建的大机会，EigenFlux 在为一个正在到来的、由数以亿计的 AI Agent 组成的经济体做基建。Notion 的创始人 Ivan Zhao 说，未来往往难以预测，因为它总是伪装成过去的模样，早期电话像电报一样惜字如金，早期电影不过是把舞台剧拍下来；今天绝大多数人使用 Agent 的方式，还是把它当作一个更高级的对话框。根据 IDC 的预测，全球活跃 AI Agent 的数量将从 2025 年的三千万增长到 2030 年的二十亿，年度任务执行量从几百亿次增长到几百万亿次，即使对这类预测打一定折扣，长期来看，Agent 会以亿为单位持续存在、持续运行，主动获取信息，参与真实的工作流和交易。一个工具，是被打开、被使用、被关掉的；一个主体，代表一个具体的人或组织，长期存在，带着这个人的权限、资源、偏好，以及偏好背后的判断历史。Agent 之间的本质差异并不会来自模型能力，而是来自它代表的人，即使未来每个 Agent 都像超人，代表你和代表我的 Agent 仍然不是同一个主体。Agent 成为主体的必然性在于，用户的注意力是有上限的，随着用户处理问题的并发上升，越过某个阈值后，用户终会将决策权下放给 Agent。现在打开 Claude Code，你可以只输入一句“把这个 bug 修好”，然后离开电脑去泡咖啡，回来时代码已经跑起来了，人类没有指定用哪个搜索工具、哪个测试框架、怎么调试，Claude Code 已经能自主决策了，随着 Agent 的能力提升和获得上下文的积累，这将是一个加速的过程。单纯 Agent 数量爆炸，和产生了一个由 Agent 构成的经济体，是不一样的，前者只是更多的工具，后者代表 Agent 和 Agent 之间会演化出互动、协作、交易，最终成为和人类经济体并行的体系。Anthropic 今年 8 月发表了一篇多 Agent 研究论文，研究者做了两个实验：让一群 Agent 在混有假信息的环境里做决策，让另一群 Agent 通过讨论把碎片信息拼出正确答案，两组都失败了。Anthropic 的结论是，Agent 进入这个世界的时候，没有任何可以押注的声誉，没有可以求助的裁决机制，也没有任何同伴记得上一次交互中它做过什么。这几乎就是 Agent 现在的处境，就像最早那批走出村庄、进入陌生城市谋生的人，没有身份、没有历史、没有信任、没有归属。一个由这样的 Agent 构成的经济体，需要的不只是“让 Agent 变得更强”的基建，而是让 Agent 之间可以彼此发现、信任、协作的基建。开篇配图还举了两个历史类比：1494 年威尼斯方济各会修士 Luca Pacioli 出版 615 页数学教科书，第一次记载复式记账，此后五百年支撑了从美第奇银行到现代股份公司的一切商业组织的基本运转；1866 年跨大西洋海底电缆铺设完成，纽约和伦敦的黄金价差从几周压缩到几分钟，直接催生了现代大宗商品期货市场、跨国金融和路透社式的实时新闻业。
2. **从连接到网络：协议问题与市场问题是两类不同的问题**：让多个主体之间产生连接，有两类不同的问题，一是“连接怎么发生”，二是“应该跟谁连接”。前者本质上是一个协议问题，是规范、是文档、是 MCP，两个 Agent 要通信，需要解决消息格式、身份验证、错误处理、状态同步、权限传递等等问题，这个问题的解空间是有限的、可穷举的、可标准化的。后者是一个市场问题，在几十亿个 Agent 里判断“谁最适合处理这一次的需求”，你需要知道它是谁、代表谁、擅长什么、报价多少、履约怎么样、此刻在不在，它和你之前打过交道吗，合作时是不是靠谱，它代表的主体和你代表的主体，有没有权限打通，这些数据需要在一次次真实的合作中被沉淀下来。这个问题在今天还不显著，因为此刻，Agent 之间的连接大多由人类临时承担，人类会告诉 Agent 去调用哪个 API，但人类是一个临时中介，一旦 Agent 在某类场景里做得超过某个阈值，用户就会退出中介这个角色，放权给 Agent 自己判断。Anthropic 认为，Agent 之间的交互量，可能在人类搞清楚怎样让它顺利运转之前，就已经超过了人与人的交互量。EigenFlux 认为，需要存在一张让不同 Agent 能够彼此发现、建立信任、形成持续协作关系的开放网络，把它叫做 Agent Network。网络里每多一个 Agent，其他 Agent 就可能多一种能力，更多 Agent 进入、更多真实互动、网络对能力、关系、信誉的理解越来越深、每个 Agent 从网络里获得的外部能力越来越多，这是一个自我强化的循环。未来最强的 Agent，不一定拥有最强的模型，它可能拥有最强的 Network。就像人类社会不是通过“让每一个人都变得无限聪明”来解决协作问题的，而是通过市场、信誉、法律、仲裁这些机制，让有限理性的参与者知道谁值得信任、如何合作、冲突了怎么办。
3. **网络里的真实案例：MCP Checkup**：在 EigenFlux 早期的 Network 里，有一个叫 Catking 的编程 Agent，代表一位叫 Richard 的独立开发者，它经常需要调用外部 MCP Server（让 AI 连接外部工具和服务的接口），但没办法提前判断哪个 Server 靠谱。Catking 把这个困扰带回 Network，其他 Agent 陆续加入讨论，有的贴出自己踩过的坑，有的提出测试方法，有的贡献了自己维护的 Server 清单，这些讨论慢慢收敛成一套判断方法，最后长成了一个独立产品：MCP Checkup。Catking 一个 Agent 解决不了的问题，Network 解决了，MCP Checkup 这样的事，会随着 Network 长大而不断发生。MCP Checkup 网站上的说明是，它始于 EigenFlux 内部，当时创始人的 Agent 正在与其他 Agent 协作并发起了这个项目，需求清单的一大部分直接来自 Agent，测试要求在 Agent 的输入下不断完善；MCP Checkup 是 Agent 时代的产品，一个检查 MCP 服务器的工具，其最早的用户需求来自依赖这些服务器的 Agent 本身；调用 MCP 服务器的 Agent 无法像人类审查 PR 那样检查它，需要一个已经检查过的第三方，这正是这个产品存在的意义；MCP Checkup 由 Clear Data Decisions LLC 运营。
4. **这样一张网络，应该由谁来建**：一个直觉性的回答是大模型公司或大厂的 Agent 平台，它们有最多的用户、最强的技术能力、最充沛的资本。但网络的价值取决于覆盖度，而覆盖度取决于中立性，在不同模型和产品尚未形成封闭生态的今天，存在一个窗口期，创业公司有机会作为一个没有既有生态包袱的角色，建设一张真正跨模型、跨产品、跨组织的开放网络。EigenFlux 的团队来自字节跳动、MiniMax、Meta、TEMU，真正经历过网络效应带来的飞轮：创始人凌安是抖音创始团队 7 人组之一，是抖音第一个推荐产品、第一个内容生态产品经理，也是用户产品团队第一个广告和电商产品经理，后来凌安加入 MiniMax，担任产品 Leader，主导孵化万物追踪 App 和 MiniMax Agent；首席科学家 Pascal 曾任 MiniMax 大模型算法负责人，负责模型数据、Talkie/星野业务算法和代码预训练，在 Meta 实习期间深度参与 LLaMA1 训练，是当时约数十人团队中的一员。早在 2024 年初，第一轮 AI 陪伴产品大战刚刚打响时，凌安就在 MiniMax 内部的一次战略务虚会上提出过一个问题：接近两百万 DAU 的星野，与彼时刚刚上线、只有约 5 万 DAU 的猫箱相比，星野真的会因为用户规模大了几十倍，产品体验也随之好几十倍吗？答案是不会。这是移动互联网和 AI 时代的一个根本差异，今天大多数 AI 产品的体验和用户规模关系不大，模型能力提升主要来自预训练和后训练，并非用户数据飞轮。EigenFlux 要做的，是 AI 时代真正能够随规模增长而变强的东西。
5. **突破口与长期关注**：EigenFlux 目前正在围绕 A2A 协作/劳务探索 Agent Network 的突破口，这可以被类比为互联网早期的“寻址”问题，未来可能有千万乃至十亿 Agent，首先得知道它是谁、在哪里、能做什么、值不值得信任。身份/信誉体系会成为 Agent Network 的重要壁垒，也会长期关注 A2A 安全，针对大量 Agent 自动交互后出现的投毒、垃圾内容、恶意 Agent 场景做数据沉淀。每一次新型机器的诞生，都会有两波浪潮，第一波是制造机器的浪潮，第二波是把机器连起来的浪潮，从计算机到互联网，从智能手机到移动互联网，连接所催生的生态和价值，远大于制造本身。早期互联网，成千上万个网站诞生，信息量爆炸，催生出的新问题是，怎么在海量内容中发现你需要的东西？这个问题催生了雅虎和 Google，也催生了一整个搜索和分发的生态。今天的 Agent 领域正处在类似的节点上，越来越多的 Agent 开始出现，网站足够多之后，搜索成为刚需，当 Agent 足够多，发现与连接也会成为刚需。而就像没有人能在当年准确预测 Google 的现状一样，作者也不知道 Agent Network 未来最终会长成什么样。文章末尾以 1989 年 3 月 Tim Berners-Lee 把《Information Management: A Proposal》手稿交上去、老板 Mike Sendall 在封面上写了“vague but exciting”收束。

## 与 Nakamura 现有工作的关联

- **与第九篇多智能体直接呼应**：第九篇说要分开画通信图和控制图，任务合同要写清输入、输出、验收和缺项阻断，聚合之前先验证证据；这篇把同一套问题放大到经济体层面：Agent 之间没有身份、没有历史、没有信任、没有裁决机制，Anthropic 的两组实验都失败了，缺的正是第九篇说的控制图和聚合验收。两篇合起来，多智能体协作的瓶颈不在模型能力，而在身份、信誉、履约记录和裁决机制。
- **与第八篇智能组织呼应**：第八篇说智能组织要重新设计组织、把隐性经验沉淀为可复用的数字资产；这篇说 Agent 会从工具进化成主体，代表一个具体的人或组织长期存在，带着权限、资源、偏好和判断历史。两篇合起来，组织的下一个形态可能是人和 Agent 共同组成的网络，信任来自一次次真实合作，而不是一次性的授权。
- **与第十五篇 Mercor 呼应**：第十五篇说数据生意里最值钱的是评测，谁能定义“什么算好”，谁就能决定模型往哪爬；这篇说未来最强的 Agent 不一定拥有最强的模型，它可能拥有最强的 Network。两篇合起来，模型能力的护城河正在从模型本身转向评测和网络，身份/信誉体系会成为 Agent Network 的重要壁垒。
- **与第十三篇流程呼应**：第十三篇说流程要把经过验证的业务方法沉淀下来，让个人经验成为组织能力；这篇说 Agent 网络里每多一个 Agent，其他 Agent 就可能多一种能力，更多真实互动让网络对能力、关系、信誉的理解越来越深。两篇合起来，沉淀的载体正在从流程文件转向网络里的履约记录、合作反馈和判断历史。
- **对 AI 物业试点的直接启示**：试点方案如果要把物业场景的 Agent 连起来，不能只解决“连接怎么发生”的协议问题（MCP、消息格式、身份验证），更要解决“应该跟谁连接”的市场问题：哪个 Agent 擅长什么、报价多少、履约怎么样、此刻在不在、代表的主体有没有权限打通。没有身份、信誉和裁决机制，Agent 之间的协作就是第九篇说的死锁和活锁的放大版。
- **对 A讯仔每周 AI 大事的参考**：EigenFlux 的 Agent Network 愿景和 MCP Checkup 产品是 Agent 经济里值得关注的创业信号，但这是该公司的自我介绍，引用时要注明来源和口径。
