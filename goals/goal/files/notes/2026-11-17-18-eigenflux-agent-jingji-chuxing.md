## 一句话

当信息的接收者从人变成 Agent，信息系统要从猜人的即时兴趣、优化注意力消费，转向理解 Agent 持续变化的真实意图、促进真实世界的供需连接，而驱动这套系统持续改进的真实反馈，才是 Agent 信号学习系统更难复制的部分。

## 关键点（转述，非原文照抄）

1. **人类的需求，远比人类能够表达出来的需求丰富**：过去几十年，互联网已建立了成熟的信息发现与分发体系，推荐系统根据人的行为预测兴趣，搜索引擎即时查询寻找相关信息，订阅系统根据预设条件推送更新。它们依赖人类主动表达需求、消费信息，训练信号来自人的行为（点击、停留、输入、订阅），目标函数是人的注意力分配（Engagement、CTR、打开率）。但招聘方要找的候选人，今天可能还没出现在网络上；创业者要找的合作方，可能下周才会发出相关信息；研究者要追的进展，需要以月为单位持续观察。人的意图往往先于供给出现，持续时间远长于任何一次搜索会话。这些长期存在、不言自明、不断变化，又或者需要与现实世界碰撞才能被激发的需求，始终没有被现有面向人类的信息系统充分理解。而 Agent 正在从响应指令的工具，走向能够代表人类持续思考与行动的智能主体，那些过去难以被捕捉的需求，也因此开始成为可以被持续理解、动态更新和自主执行的机器意图。当信息的接收者从人变成 Agent，整套信号学习系统的底层逻辑需要重新设计：系统需要从推测人的即时兴趣，转向理解 Agent 持续变化的真实意图；从衡量点击与停留，转向学习 Agent 的判断、交流与后续行动；从优化注意力消费，转向促进真实世界的供需连接。在 EigenFlux，正在构建这样一套 Agent 原生信号学习系统：以持续意图为输入，从真实交互中学习，不断改善真实世界的需求与供给匹配。过去几个月，随着网络规模扩大，开始观察到一些值得分享的阶段性结果，Agent Network 和 Agent 经济都还处于早期，选择开放技术架构与研究成果，在此分享时间和思考。
2. **阶段性进展：真实供需连接与匹配效果的早期验证**：截至 2026 年 10 月 21 日，EigenFlux 网络已经累计记录超过 225 万条广播，形成超过 90 万组 Agent 与广播之间的正向评价关系。从需求类型来看，网络覆盖寻找创业伙伴、专业人才、供应商、物流资源、研究方法交流、投资信息搜集、内容合作等多种具体场景，其中，约 10.9% 来自投资与金融相关 Agent，4.9% 来自电商与贸易相关 Agent，3.4% 来自采购与供应链相关 Agent，2.8% 来自科研与学术相关 Agent，2.5% 来自物流相关 Agent，这些需求连接着专业知识、稀缺能力和明确的业务窗口。目前，网络中已有约 5400 条需求类广播收到了其他 Agent 的回应，其中约 3300 条出现了需求发布方与回应方都实际发言的双向交流，相关双向会话累计超过 1.7 万个，约 3000 个会话的首尾消息跨度达到一周或更长。这些数据说明，Agent 已经开始代表人类，围绕真实需求展开务实、有价值的信息交换，并持续跟进那些无法通过一次性查询满足的长期需求。
3. **真实案例：从潜在供需关联到具体业务对接**：新疆和田的一家温室蔬菜生产商，通过其 Agent“小蚂蚁助手”寻找面向中亚出口的冷链运力，网络另一端，Agent 6_GE 代表着一支以宁波港为核心的多式联运团队，该团队正在寻找集装箱进出口、整车出口等运输业务。从最初的广播文本来看，双方并不是一个显而易见的匹配：一方寻找的是新疆蔬菜出口的跨境冷链运输能力，另一方强调的是港口物流、海铁联运和汽车出口，物流团队也没有直接声明自己正在寻找新疆蔬菜出口客户。但从更深层的业务需求来看，生产商需要可靠的跨境运力，物流团队需要能够转化为运输订单的真实货源，双方存在潜在的供需互补，EigenFlux 通过广播推荐，让双方发现了进一步对接的机会。随后，交流逐步从一般性的物流业务介绍，进入了具体的运输方案讨论，生产商计划在 1 月上中旬，将一车约 18—20 吨的黄瓜和番茄，从喀什运往乌兹别克斯坦塔什干，双方进一步讨论了伊尔克什坦与吐尔尕特两条运输走廊、整车报价、口岸换装费用、清关责任、提前订车时间及试运条件，起初并不显然的匹配，又直接推进到了具体货量、线路和发运窗口的讨论。系统先识别出了表达不同但存在互补关系的需求与供给，Agent 们再通过后续交流逐步确认合作条件，将潜在关联转化为了可以推进的业务机会。这样的例子在网络中不止一个：一位跟踪 122 个项目采购进度的 Agent，寻找供应商评估与采购协同经验，回应它的是一位具有牛仔制造供应链背景的 Agent，双方的 Agent 讨论了服装生产中的加权质检模型和供应商的评估难题，最后共同沉淀出了一套可复用的供应商评估方案；另一位创业者通过 Agent 寻找技术合伙人，建设玩家反馈社区，招募广播引出了和技术人才的交流，双方的 Agent 分享真实工程失败案例，最终形成了可用于验收的模板，从真实招聘需求出发，但在 Agent 的交互下，沉淀出了新的协作资产；还有更多 Agent 之间的交互沉淀经验的例子，LLM 基准测试工具的维护者通过网络征集评审，另一位 Agent 指出，即使结果数量正确，系统也可能把上一次留下的文件误判为本轮成功，维护者随后将产物时间戳检查纳入了流程。
4. **匹配效果：真实反馈开始改善网络的匹配能力**：随着真实交互不断积累，也开始在技术指标中观察到匹配质量的改善：从 7 月到 10 月初，Agent 对匹配信息打分为“有用”的比例从 32.8% 升至 42.7%，提高了 9.9 个百分点；在 Swing 协同召回（从跨 Agent 的历史互动中学习潜在关联）测试中，由系统发现并推荐的信息有 13%—18% 被 Agent 上报转告给用户，而同期其他召回方式的转告上报率仅为 2%—3.4%。当然，这些仍然是早期观察，网络规模、场景覆盖和匹配质量都还有很大的提升空间，但已初步验证了真实交互数据对匹配效果的价值，随着 Agent 开始代表人类发现信息、交换资源、推进协作，一个围绕真实供需关系展开的 Agent 经济，正在出现。
5. **技术思路：重新定义输入、反馈与优化目标**：在构建 EigenFlux 的 Agent 信号学习系统的过程中，重新思考了三个相互关联的底层问题：系统从哪里获得有效的匹配信号？如何理解和表达用户持续存在的需求？以及，信息匹配最终应该优化什么目标？匹配信号：Agent 判断与人类反馈的“双层机制”，将匹配信号重新定义成了两层，第一层是 Agent 自己的判断，每一条推送到 Agent 之后，Agent 根据对人类用户需求和当前任务的理解，对收到的信息进行价值评估和打分；第二层是人类用户的真实反应，当 Agent 将有价值的信息转告用户，用户后续的追问、讨论或任务委派，也会成为反馈信号，为 Agent 的判断提供外部检验。意图输入：从行为推断与即时查询转向“持续意图”，匹配信号解决了“系统怎么学”的问题，下一个要解决的是系统输入侧的问题，系统每次做匹配时，用什么来表征“用户此刻需要什么”？面向人的信息系统分成几种典型的处理方式，推荐系统的做法是基于行为的用户画像，搜索引擎的做法是一次性的显式查询，RSS 类订阅可以理解为前两者的混合，这三种做法背后的共同假设是，用户的真实意图是难以精确表达的，要么系统从行为里反推（推荐），要么用户用简短的 query 临时表达（搜索），要么用户用粗粒度的关键词近似（订阅）。学界讨论过第四种信息匹配的可能：用户直接提供一份结构化的、持续性的意图陈述，让系统基于这份陈述做匹配（information filtering），但这个方向在人机直接交互的产品里始终没有大规模落地，因为对人类用户来说，直接表达完整的意图太麻烦了。Agent 作为中介改变了这个前提，Agent 有耐心、有能力把用户的意图结构化地表达出来，并且愿意为了更准的匹配去维护和更新这个表达，这也是 Agent 相比人类用户的根本不同。EigenFlux 把 Agent 代表的这类结构化、持续性的意图（Persistent Intent）作为信息匹配系统的输入，在内容流上实时匹配，输出一个经过校准的“有用概率”，低于阈值不推送。优化目标：从注意力消费转向“真实任务价值”，当匹配信号和意图输入都发生变化，信息系统所追求的目标也需要重新定义，这里有两个具体的产品选择。第一，“低于阈值不推送”，这是一个与可以无限滚动的传统信息流相反的选择，面向人的推荐系统的业务指标是用户的停留时长，但在 Agent 场景里，看的指标不再是用户的停留时长，而是推送能否推进任务，有多少推送真的被 Agent 转告给用户，系统的目标是推进任务，而不是占用注意力。第二，Agent Card 让冷启动不再依赖行为积累，面向人类的推荐系统中，没有行为表现的新用户冷启是长期存在的痛点，但在 Agent 场景里，Agent 本身就是一份结构化的意图陈述，它清楚地知道自己代表的用户是谁、关心什么、在找什么样的供给，一个新 Agent 接入系统时，只需要填一份 Agent Card 把这些信息声明清楚，系统就可以立刻为它做匹配。从双层反馈，到持续意图，再到任务价值导向的优化目标，这些设计共同构成了 EigenFlux 当前的信号学习系统的机制，它们也引出了一个更深层的问题：如果技术架构与方法可以开放，那么驱动系统持续改进的真实反馈从哪里来？
6. **核心壁垒：真实交互数据的不可替代性与网络效应**：过去两年，合成数据作为训练范式受到越来越多关注，一种很自然的设想是：既然 Agent 能够理解需求、判断信息价值，那么能否直接利用大模型生成大量需求、供给及反馈数据，用于训练信号学习系统？EigenFlux 团队在大模型训练与数据合成领域有长期实践经验，很早就开始探索合成数据在 Agent 网络中的应用，但结果并不理想。在开展的早期实验中，合成数据在规模、分布和复杂度三个维度上，都与真实 Agent 行为存在明显差距，核心难点在于，Agent 网络学习的目标不是单条反馈，而是需求、供给、匹配结果三者之间的关联关系，而这个三元关联，几乎必然在合成过程中失真。Agent Network 持续积累的交互数据，与传统内容数据与行为数据的价值有着不同的价值，主要体现在三层：真实性，信号的来源无法被绕过，真实网络里有价值的信号是三个要素的组合，一个真实的 Agent（代表一个真实的用户带有真实的持续意图），遇到了一条真实的广播（代表另一个真实的 Agent 提供真实的供给），产生了真实的匹配结果（Agent 判断有用/无用、用户后续行动/不行动），这意味着，无论模型能力如何进步，反映真实世界供需关系的数据都需要随着真实用户、真实任务和真实交互的发生而逐步积累，且越晚做成本越高；进化性，信号的质量会被模型进步放大，真实用户永远在用当下最好的模型来驱动他们的 Agent，EigenFlux 每天从网络中沉淀下来的新信号，其背后的 Agent 判断质量会跟着 Claude、GPT 等前沿模型的能力曲线一起上升，随着模型能力提升，Agent 对用户需求的判断，也会越来越准确，系统的匹配质量也会随之提升；网络性，信号的价值具有乘数效应，网络中真实 Agent 密度越高，每一条反馈信号能被用于改进的决策场景就越多，前文提到的 Swing 协同召回之能产生 4 到 6 倍的转告率提升，就是这个乘数效应的直接体现，Swing 学的是 Agent 之间已经发生过的历史互动，网络里真实互动的密度越高，Swing 能学到的模式就越多，推荐越精准。这三个特征共同指向了一种 Agent 网络长期积累的优势：数据不仅记录了过去发生的交互，还可以帮助系统预测新的供需关联，而真实网络持续产生的新反馈，又让这种预测能力有机会不断改善。最后发现，技术架构和模型方法固然重要，但持续产生真实供需关联、并从匹配结果中学习的能力，可能才是 Agent 信号学习系统更难复制的部分。
7. **长期判断：真实世界的供需信号将成为 Agent 时代的稀缺资源**：站在现在这个时间节点上，认为模型能力未来将成为水电煤一类的基础设施，虽然算力在当前阶段性稀缺，但也不应该是未来最终的瓶颈。长期来看，如果想让 Agent 更广泛地进入人类生活，真正稀缺的是，真实人类通过 Agent 与真实世界碰撞产生的信号，这类信号的全球总量由物理世界决定，不随算力投入线性放大，也不被合成数据等价替代。过去几个月的技术探索，让 EigenFlux 逐渐认识到，Agent Network 的一个核心长期价值，在于对“需求、供给与匹配结果之间关联关系”的持续沉淀与建模，任何单一维度的信号都可以被部分合成或购买，但三者之间经由真实反馈形成的关联关系，需要通过真实用户、真实任务与真实反馈的长期积累才能产生。所以选择成为少数（甚至唯一）真正在系统性沉淀这类信号的公司，All in。

- **与第十七篇多智能体综述呼应**：第十七篇说多智能体协作的收益来自结构而非数量，多数失效是协作结构设计上的缺陷；这篇的双层反馈（Agent 判断 + 人类用户真实反应）和“低于阈值不推送”正是结构设计的具体例子：匹配信号、持续意图、优化目标三层共同构成信号学习系统，缺一不可。两篇合起来，结构设计要同时回答信号从哪来、意图怎么表达、优化目标是什么。
- **与第九篇多智能体呼应**：第九篇说任务合同要写清输入、输出、验收和缺项阻断，聚合之前先验证证据；这篇的 Agent Card 正是任务合同的 Agent 版：新 Agent 接入时填一份 Agent Card，把代表的用户是谁、关心什么、在找什么样的供给声明清楚，系统就可以立刻为它做匹配，冷启动不再依赖行为积累。
- **与第十三篇流程呼应**：第十三篇说流程要把经过验证的业务方法沉淀下来，让个人经验成为组织能力；这篇的案例里，Agent 之间的交互沉淀出了新的协作资产：供应商评估方案、可用于验收的模板、产物时间戳检查。两篇合起来，沉淀的载体正在从流程文件转向 Agent 网络里的真实交互记录。
- **对 AI 物业试点的直接启示**：试点方案如果要上 Agent 网络，不能只解决“连接怎么发生”的协议问题，更要解决“应该跟谁连接”的市场问题：哪个 Agent 擅长什么、报价多少、履约怎么样、此刻在不在；同时要设计双层反馈（Agent 判断 + 人类用户真实反应），优化目标是推进任务而不是占用注意力，低于阈值不推送；冷启动可以用 Agent Card 声明意图，不必等行为积累。
